# MarketLens

A self-contained, end-to-end data platform built from scratch on a simulated
e-commerce electronics shop — real product data in, through an event stream,
into a modeled warehouse, orchestrated on demand. Built as a structured
learning project, but engineered to the same standards as production work:
idempotent scripts, environment-based config, containerized infrastructure,
tests, and deliberate scoping decisions explained inline rather than glossed
over.

Each stage is its own sibling project with its own README and design doc
(`PLAN.md`), so the chain can be read top to bottom or picked up at any one
stage in isolation.

```
catalog_sourcing/  →  store_db/  →  streaming/  →  warehouse/
  (real product        (Postgres      (Kafka event    (dbt + DuckDB
   catalog via API)      OLTP db)       stream)         bronze/silver/gold)
                                                              ↑
                                                    orchestration/
                                                    (Airflow, on demand)
```

## Why it's built this way

- **Real data where it matters.** The product catalog isn't fabricated — it's
  sourced live from a public product-lookup API, then a full year of orders,
  pricing, inventory, returns, and reviews is simulated on top of it with a
  seeded, reproducible generator (not random noise — demand, pricing, and
  review sentiment all correlate the way a real shop's data would).
- **Event-driven, not batch-loaded.** The simulated year is replayed through
  Kafka topic-by-topic, consumed into raw ("bronze") Parquet files, the same
  shape a real production system would hand off to analytics — not a direct
  database dump.
- **A real medallion architecture.** dbt + DuckDB turn bronze into deduplicated,
  typed "silver" models and purpose-built "gold" marts (revenue, price
  elasticity, inventory turnover, return rate, review ratings) — with the
  underlying data-quality issues (e.g. numeric fields arriving as strings from
  JSON serialization) found and fixed the way they would be in any real
  pipeline, not hidden by clean synthetic generation.
- **Orchestration scoped honestly.** Airflow automates exactly the one step
  that's genuinely a repeatable batch job today — rebuilding the warehouse —
  and is deliberately *not* wired to a schedule or to the upstream stages
  yet, because those stages don't yet support incremental (only full) runs.
  That boundary, and the plan for closing it, is written down rather than
  faked.

## Project layout

| Project | What it does | Stack |
|---|---|---|
| [`catalog_sourcing/`](catalog_sourcing) | Pulls real electronics products (380+) from a public product-lookup API into a local JSONL cache. | Python, pandas, Jupyter |
| [`store_db/`](store_db) | Seeds a Postgres OLTP database with a full simulated year on top of that catalog: merchants, inventory, customers, orders, pricing history, payments, shipments, returns, reviews — 13 tables, generated by a seeded, idempotent script pipeline. | Python, Postgres, Docker |
| [`streaming/`](streaming) | Replays that simulated year through Kafka (7 topics, KRaft mode) as if it were happening live, and consumes it into partitioned, raw "bronze" Parquet files. | Python, Apache Kafka, Docker |
| [`warehouse/`](warehouse) | Transforms bronze Parquet + live Postgres reference data into 8 deduplicated/typed "silver" models and 5 aggregated "gold" marts. | dbt, DuckDB |
| [`orchestration/`](orchestration) | An Airflow DAG that rebuilds the warehouse on demand, running inside a Docker Compose stack with its own metadata database. | Apache Airflow, Docker |

## Getting started

Each project can be run on its own — see its README for exact steps — but the
full chain, in order:

```bash
# 1. catalog_sourcing/ — already has a cached catalog checked into data/catalog/
#    (re-run the notebooks only if you want to grow it further)

# 2. store_db/ — seed the simulated year
cd store_db && cp .env.example .env && docker compose up -d && uv sync
bash scripts/run_all.sh   # or run 01-10 individually, see store_db/README.md

# 3. streaming/ — replay it through Kafka into bronze Parquet
cd ../streaming && cp .env.example .env && docker compose up -d && uv sync
uv run python -m producers.create_topics
# then work through notebooks/01_replay.ipynb and 02_consume.ipynb

# 4. warehouse/ — build silver + gold on top of bronze
cd ../warehouse && cp .env.example .env && uv sync
set -a && source .env && set +a
uv run dbt run --profiles-dir .

# 5. orchestration/ — same warehouse rebuild, via Airflow instead of the CLI
cd ../orchestration && cp .env.example .env
docker compose up -d --build
# open http://localhost:8090, set the store_db_postgres_password Variable,
# then trigger the warehouse_pipeline DAG
```

## Roadmap

Planned next sibling projects, in order: `ml/` (PyTorch + MLflow, trained on
the gold layer), `agents/` (LangGraph + FastAPI, over the warehouse and the
catalog), `infra/` (CI/CD + cloud deployment). Also planned: an incremental
regeneration path for `store_db`/`streaming`, which would let
`catalog_sourcing`'s ongoing catalog growth flow through the whole chain on a
real schedule instead of a manual full rebuild.
